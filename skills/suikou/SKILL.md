# suikou

技術文書の草稿から、AI が書いたと分かる癖を取り除く。
そのうえで、後から保ちやすい形にするためのものである。

## 書き始める前に

`suikou brief` を動かして、出てきた縛りを守って書く。

```sh
suikou brief --profile oss --lang ja
```

brief が出すのは、指示で守れることだけである。
語彙や文の組み立ての指標は指示では変わらないと分かっているため、そこには入らない。
それらは書いたあとに `suikou check` で直すことになる。

## 考えと成果を分ける

成果のファイルには、決まった中身だけを書く。

次のものは `.suikou/notes/<成果と同じ名前>.md` に書く。

- 考えた選び方と、落とした案。
- 確信のない細かい値。
- 根拠と、測った出どころ。
- 後で確かめたいこと。

この分け方には二つの効き目がある。
考えを示したいという癖に行き先を与えることで、成果から細かすぎる書き方が減る。
それに加えて根拠が文書の隣に残るため、後の直しで「なぜこう書いたか」をたどれる。

notes は lint の対象にしない。

## 書いたあとに

`suikou check` を一度だけ動かす。

```sh
suikou check docs/guide.md
```

そのレポートは二つに分かれている。

- 「書き直しの方針」は文書の全体の傾きを示す。位置を持たない。
- 「直す箇所」は行を特定できる指摘である。

その両方を読んだうえで、直しを一度で行う。
方針だけを見て全体を書き直したり、箇条書きの指摘だけを直したりはしない。

直し終わったら `suikou check --quiet` で確かめる。

## 繰り返さない

check と直しを何度も往復させない。
一度の check ですべての層の指摘が出るため、一度の直しで足りるためである。
確かめのための二度目までとする。
