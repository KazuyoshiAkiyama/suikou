# suikou

技術文書の草稿を、AI が書いたと分かる特徴を取り除いた上で、後から保守しやすい形にする。

## 書き始める前に

`suikou brief` を実行し、出力された制約を守って書く。

```sh
suikou brief --profile oss --lang ja
```

brief が出すのは、指示で守れることだけである。
語彙や文構造の指標は指示では変わらないと分かっているため brief には含まれない。
それらは書いた後に `suikou check` で直す。

## 思考と成果物を分ける

成果物のファイルには、確定した内容だけを書く。

次のものは `.suikou/notes/<成果物と同じ名前>.md` に書く。

- 検討した選択肢と、却下した案
- 確信のない具体値
- 根拠と、測定の出典
- 後で確認したいこと

この分離には二つの効果がある。
考えを示したいという傾向に行き先を与えることで、成果物から過剰な具体性が減る。
根拠が文書の隣に残るため、後の保守で「なぜこう書いたか」を辿れる。

notes は lint の対象にしない。

## 書いた後に

`suikou check` を一度だけ実行する。

```sh
suikou check docs/guide.md
```

レポートは二つに分かれている。

- 「書き直しの方針」は文書全体の傾向を示す。位置を持たない
- 「直す箇所」は行を特定できる指摘である

両方を読んだ上で、修正を一度のパスで行う。
方針だけを見て全体を書き直したり、箇条書きの指摘だけを直したりしない。

修正が終わったら `suikou check --quiet` で確認する。

## 繰り返さない

check と修正を何度も往復しない。
一度の check で全ての層の指摘が出るため、一度の修正で足りる。
検証のための二度目の実行までとする。
