# suikou

suikou は、技術文書のドラフトに含まれる AI 執筆特有の癖を除去し、メンテナンス性の高い構成へ整えるツールである。

## 本文より前の構成の確定

文書を最初から作成する際は、本文を執筆する前に全体の構成を確定させる。

```sh
suikou plot docs/guide.md --doctype howto
```

このコマンドを実行すると、`.suikou/plans/docs/guide.md` に各節の見出しと、それぞれの節で答えるべき問いが生成される。各節の主張を一行で記述し、人間の承認を得たうえで本文の執筆へ進む。主張を一行に要約できない節は、内容の整理が不十分であると判断する。

文書種別には `design`、`decision`、`howto`、`reference`、`overview` のいずれかを指定する。プロットは構成検討のための作業ファイルであるため、バージョン管理の対象に含めない。

## 執筆前の指針の確認

執筆に着手する前に `suikou brief` を実行し、出力された指針と制約に従って本文を作成する。

```sh
suikou brief --doctype howto --lang ja
```

`--doctype` を指定すると、禁止事項の一覧よりも前に、各節で答えるべき問いと執筆の指針が出力される。取るべき記述方針を先に提示し、避けるべき表現を後に配置する順序になっている。

brief が提示する制約は、事前の指示だけで遵守可能な項目に限られる。語彙や文構造に関する指標は事前指示では改善しないことが分かっているため、ここには含まれない。これらの指標は、執筆後に `suikou check` を使って修正する。

## 思考の過程と成果物の分離

成果物のファイルには、確定した内容だけを記載する。検討過程のメモや未確定の情報は、`.suikou/notes/<成果と同じ名前>.md` へ書き出す。

- 検討した選択肢および不採用とした案。
- 確証のない細かな値。
- 記述の根拠と計測データの出典。
- 後から検証が必要な項目。

この2つを分離しておくと、思考の過程を書き出したい場合の記録先が確保されるため、本文に過剰な詳細が混ざるのを防げる。加えて、判断の根拠がその別ファイルに保存されるため、後の改訂時に記述の理由を確認できる。

notes は lint の検査対象から除外する。

## 執筆後の検査と修正

執筆を終えたら、`suikou check` を一回だけ実行する。

```sh
suikou check docs/guide.md
```

出力されるレポートは、粒度の異なるセクションで構成される。

- 「書き直しの方針」は文書全体の傾向を示す指摘であり、特定の行位置を持たない。
- 「修正する箇所」は該当する行を特定できる個別の指摘である。

双方の内容を確認したうえで、すべての修正を一回でまとめて行う。方針だけを参照して全文を書き直したり、箇条書きの指摘だけを部分的に直したりしてはならない。

`structure/` で始まる指摘は、文書の構成に関する問題を表す。節の欠落、節の順序の誤り、一段落に複数の主張が含まれる状態が該当する。これらは文面の調整では解消できないため、節の追加・削除または段落の分割によって対処する。プロットを用意している文書で構成を変更した場合は、プロット側も合わせて更新する。

修正が完了したら、`suikou check --quiet` を実行して結果を検証する。

## 反復の禁止

check と修正を何度も繰り返してはならない。一回の check ですべてのレイヤーの指摘が一覧で得られるため、修正は一回で完結する。実行は確認用の二回目までに留める。
