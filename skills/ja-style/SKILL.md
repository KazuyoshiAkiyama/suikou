# ja-style

ja-style は、日本語の技術文書を後から保ちやすい文体へ整えるための規約である。文体の形式と、それが満たすべき実測値、および検証の手順を扱う。

実測値は suikou リポジトリの日本語文書9件を測定して定めた。語彙の選定手順は `docs/content/ja/writing.md`、各指標の定義は `docs/content/ja/metrics.md` にある。

## 書いたものを検証する

**書き終えたら必ず検証する。**この手順を省くと、以下の規約を守ったつもりの文書が実際には閾値を超過する。

```sh
suikou check docs/guide.md --format json
```

合格は error と warning がゼロ件であることとし、info は参考情報として読む。

**ただし `check` は以下の規約を検証しない。**漢語率の下限、1行の長さ、見出しの形式、冒頭が定義文であることは、いずれも自分で読み返して確かめる。検証が通ったことは、規約をすべて守った証拠にはならない。

判定に `grep 'warning'` を使ってはならない。`--format text` は指摘の行に severity を印字しないため、この検索は常に0件を返す。JSON の `severity` 欄で判定するか、局所の指摘だけを数える。

```sh
suikou check docs/guide.md --format text | grep -c ':[0-9]*:[0-9]*:'
```

終了コードでも判定してはならない。`--quiet` は error が発生したときにのみ 1 を返し、warning では 0 を返す。

## 実測値を満たす

| 項目 | 満たす値 | 検証 |
|---|---|---|
| 指示詞の密度 | 本文1000字あたり 4.5 以上 | `ja.demonstrative_per_1k` |
| 漢語率の上限 | 0.59 まで | `ja.kango_ratio` |
| 一段落の文数 | 6 まで | `structure/long-paragraph` |
| 地の文の比率 | 0.75 以上 | `ja.prose_ratio` |
| 漢語率の下限 | 0.50 以上 | 自分で測定する |
| 1行の長さ | 中央値 92 字 | 自分で読み返す |

下段の2項目は `check` が検証しない。漢語率の下限を測定するには、`--format json` の `ja.kango_ratio` の `value` を読む。閾値の範囲内に収まる指標は `--format text` では出力されないため、JSON で読む必要がある。

漢語率には**下限がある**。漢字の割合を下げる目的で和語へ置き換えてはならない。`確認`、`使用`、`停止`、`動作` のように技術文書で定着した漢語はそのまま用いる。和語へ寄りすぎた文は `register/rare-wago` が検出する。

指示詞の密度は、語を足して稼ぐものではない。段落の冒頭で直前の段落の主題を名詞で繰り返している箇所を、`この`、`その`、`これら` へ置き換える。

## 冒頭と見出しを整える

冒頭の段落は、主題を主語に置いて、それが何であるかを述べる定義文にする。背景、目的、経緯から始めてはならない。`structure/lead-opener` が検出する。

```markdown
suikou は、日本語と英語の技術文書を対象とする lint ツール兼執筆ハーネスである。
```

見出しの形式は文書の種類に応じて決まる。リファレンスと設計の文書では体言止めの名詞句にする（`実測値に基づく規則設計`）。手順を示す文書とスキルでは動詞で終える（`書いたものを検証する`）。いずれの種類でも見出しに連番を付けない。

## 段落と文を整える

段落は折り返さず1行にまとめる。1行の長さは中央値 92 字を目安とし、文の途中で改行を入れない。差分が語単位ではなく段落単位で出るため、改稿の履歴が読める形式になる。

一段落に置く主張は1つに絞る。一文は中央値 45 字を目安とする。文末は `する` と `である` を主体とし、`ない` に偏らせない。

理由は `〜ためである` で明示する。具体例は `具体的には`、`たとえば`、`具体例として` で導入する。表のセルには `実装済み（単体テストあり）` のように括弧で補足を添える。

## 箇条書きを整える

箇条書きの直前には完結した文を置く。導入文と各項目が文法的に連続する構文を避ける。

地の文に項目の総数を書いてはならない。`次の三点を書く` と書くと、項目を増減したときに本文が実態と一致しなくなる。`maint/item-count` が検出する。

同じ箇条書きの中では項目の末尾の形式を揃える。体言止めと述語止めを混ぜない。`maint/parallel-items` が検出する。

## 避ける表現を知る

時点に依存する表現を使わない。`既存の`、`現在`、`最新の` はいずれも基準が動く。時期に言及する場合は西暦またはバージョン番号で固定する。`maint/time-dependent` が検出する。

暗喩を用いない。比喩が必要な場合は直喩または例え話にする。

身体動作を連想させる和語を避ける。`除外する`、`除去する`、`検出する`、`統一する` のような、動作ではなく処理を述べる漢語を用いる。`glossary/variant` が検出する。

進行状況や検証で判明した事項といった著者の備忘録を本文に残さない。読み手に要るのは結果である。その経緯は決定の記録へ移す。`structure/work-note` が検出する。

## 語彙を手順で選ぶ

語の選定を語感に委ねない。置換する前に、参照コーパスでの出現数を測定する。

```sh
python3 - <<'PY'
import re, glob
INLINE = re.compile(r"`[^`]*`|\{\{[^}]*\}\}|\[([^\]]*)\]\([^)]*\)|<[^>]+>")
FENCE = re.compile(r"```.*?```", re.S)
word = "根因"
n = sum(INLINE.sub(lambda m: m.group(1) or " ", FENCE.sub(" ", open(p, errors="ignore").read())).count(word)
        for p in glob.glob("corpus/cache/pro_ja/**/*.md", recursive=True))
print(n)
PY
```

コードブロックとインラインコードを除外する。生のファイルへ `grep -c` を当てると、コード内の語まで計上される。活用する語は語幹で数える。

出現数が0件の語は、その分野で書かれない語である。定着した漢語へ置換する。0件の語を残す場合は、参照コーパスの分野が適合しない理由を併記する。参照コーパスは API の説明であるため、文法と統計の術語（`体言止め`、`偽陽性`）はこの例外に当たる。

意味が限定されない語を別の限定されない語へ置き換えても効果はない。`置く` と `設定する` は対訳の収束率がいずれも 67% で同程度であり、`配置する` が 100% である。語種ではなく、意味がどの程度限定されるかで選ぶ。

## 閾値が合わないときの扱い

閾値が対象の文書に適合しない場合は、`.suikou/profile.toml` に実測値を根拠として書き、`reason` に経緯を残す。

`suikou baseline` の出力をそのまま採ってはならない。この較正は Tukey の上側フェンスであり、コーパス内の外れ値を見つけるためのものである。サンプルが少ないと、実測の最大値を大きく超える位置に落ちる。

指標を最小化すること自体を目的にしてはならない。漢語率は info レベルの参考値である。
