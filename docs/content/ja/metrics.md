Rust の実装が満たすべき定義をここに置く。
`research/` の Python が参照の実装であり、`tests/golden/` がその出力を固定している。

形態素解析器が lindera と fugashi で違うため、値が完全にと合うことは求めない。
照合には許容範囲を置く。その幅を超えた指標が出た場合は、
どちらの実装が正しいかをそのつど決める。

## 前処理

順序が結果を変更する。次の順で行う。

1. YAML のフロントマターを取り除く
2. 囲みのコードブロックを取り除く
3. **バックスラッシュのエスケープを戻す**（`\.` を `.` に戻す）
4. HTML のタグを取り除く
5. 行をブロックに分類する
6. 行の中の記法（リンク、コード、強調）を取り除く

三つめを飛ばすと文分割が成り立たない。
AWS の doc_source がこの形式であり、戻さない場合の平均文長は3倍以上にふくらむ。
`tests/golden/input/en_escaped.md` がこの振る舞いを固定している。
戻す前の文の数は6、戻したあとは11である。

### ブロックの分け方

| 種類 | 判別方 |
|---|---|
| 見出し | 行頭が `#` 1個から6個と、それに続く空白 |
| リスト項目 | 行頭の空白に続いて `-` `*` `+` のいずれか、または数字と `.` か `)`、その後に空白 |
| 表 | 行頭が `\|` |
| 引用 | 行頭が `>` |
| 地の文 | 上のいずれでもない、空でない行 |

### 何を対象にするか

| 指標の種類 | 対象 |
|---|---|
| 語彙（MATTR、漢字率、漢語率、指示詞、形式名詞） | 地の文とリスト項目の本文 |
| 文の構成（文長、読点、文末、連用中止、テ形接続） | 地の文だけ |
| 書式（地の文比率、箇条書き比率、太字） | すべての行 |

語彙の指標を地の文だけで測定してはならない。
出力の大半が箇条書きになる模型があるためである。
その場合、本文の8割以上を破棄することになる。

## 文分割

日本語は `。` `！` `？` の直後で切る。
5文字未満のもの、または日本語の文字を含まない切れ端は破棄する。

英語は spaCy の分割に従う。
記号を除いたトークンが4個未満の文は破棄する。

## 日本語の指標

形態素解析には UniDic を使う。IPADIC では語種も活用形も取れないためである。

### ja.mattr100

窓の幅を100トークンとする移動窓を取る。
窓ごとの異なり語の数を窓の幅で割って、すべての窓で平均する。
トークンの数が窓の幅未満の場合は、全体の異なり語の数をトークンの数で割る。
トークンは表層形とする。

人間は 0.559 から 0.581、AI は 0.629 から 0.665。閾値は 0.60 とする。

### ja.renyo_per_1k（連用中止）

動詞であって、活用形が「連用形」で始まり、
直後のトークンが読点である箇所を数える。
地の文の文字数（空白を除く）で割って1000倍する。

### ja.te_per_1k（テ形接続）

表層形が `て` か `で` であって、品詞の細分類が接続助詞であり、
直後のトークンが読点である箇所を数える。同様に1000文字あたりに修正する。

### ja.renyo_te_ratio

`renyo_per_1k` を `te_per_1k` で割る。
割る側が 0.05 未満の文書では、この比を出さない。

人間のネイティブは 2.00、人間の翻訳は 1.79、AI は 3.62 から 15.94。閾値は 3.0 とする。
この指標がいちばん強く分割する。
テ形は話し言葉に寄っていて、節をひとつにまとめる。
連用中止は書き言葉に寄っていて、節を並べる。
AI は後者に偏る。これは英語の分詞節が多すぎることと同じ現象にあたる。

### ja.keishiki_meishi_per_1k（形式名詞）

品詞が名詞であって、表層形が `こと` `もの` `ため` `よう` `点` `場合` のいずれかである
トークンを数える。1000文字あたりに修正する。

人間は 11.1、AI は 4.99 から 6.95。閾値の 8.5 を下回ったら指摘する。
**これは不足していることの指摘である**ため、指摘の位置を持たない。

書かせる文書の種類に敏感である。手順書では AI 側が 8.11 まで上がって閾値に近づく。
種類ごとの人間の値が一致するまで、severity は info に置く。

### ja.demonstrative_per_1k（指示詞）

表層形が `これ` `それ` `この` `その` `これら` `それら` `こちら` `そちら` `ここ` `そこ`
のいずれかであるトークンを数える。1000文字あたりに修正する。

人間は 5.69 から 6.47、AI は 1.38 から 3.39。閾値の 4.5 を下回ったら指摘する。
これも不足していることの指摘である。日本語のゼロ照応と関わる。

### ja.kango_ratio（漢語率）

自立語（名詞、動詞、形容詞、副詞、形状詞）のうち、
語種が `漢` であるものの比率を出す。
割る側は、語種が `和` `漢` `外` `混` のいずれかであるものの数とする。

人間は 0.326 から 0.397、AI は 0.455 から 0.519。閾値は 0.42 とする。
書かせる文書の種類と話題に敏感であるため、severity は info に置く。

### ja.kanji_ratio（漢字率）

対象の文の中にある漢字（U+4E00 から U+9FFF）の数を、
日本語の文字（ひらがな、カタカナ、漢字）の数で割る。

### ja.prose_ratio と ja.list_ratio

地の文比率は、地の文の文字数を「地の文とリスト項目の本文」の文字数で割る。
箇条書き比率は、リスト項目の行数を、空でない行の数で割る。

どちらも空白を除いて数える。

## 英語の指標

確認を成功したものは三つだけである。
分詞節と名詞化は人間の範囲と重なった。
先行研究が挙げた5.3倍という効果は、文書を書かせるという仕事には移らなかった。

### en.mattr100

日本語と同じ定めとする。
トークンは小文字にした表層形とし、記号と空白は除く。

人間は 0.58 から 0.69、AI は 0.72 から 0.82。閾値は 0.71 とする。
AI のすべての条件が、人間のすべてのコーパスを上回る。いちばん安定した指標である。

### en.prose_ratio

日本語と同じ定めとする。人間は 0.66 から 0.97、AI は 0.31 から 0.56。閾値は 0.65 とする。

### en.simile_marker_per_1k

次の語句の出る数を数えて、1000語あたりに修正する。大文字と小文字は区別しない。

`like a` / `like the` / `as if` / `as though` / `akin to` / `similar to` /
`think of it as` / `imagine` / `analogous to` / `for example` / `for instance`

人間は 0.84 から 2.54、AI は 0.00 から 0.60。閾値の 0.8 を下回ったら指摘する。

AI は比喩を表す語彙をよく使う一方で、比喩であることを示さない。
この指標は、暗喩を避けて、直喩と例え話を使うという方針に対応する。

## M 系の規則

### M1 箇条書きの導入文

リストの直前にある、空でない行を導入文とする。
直前が見出しかリストである場合は判じない。

日本語の分け方を示す。

| 結果 | 条件 |
|---|---|
| ok | 行末が `。` `！` `？` |
| ok | 行末が `:` か `：` で、その直前のトークンの品詞が名詞、接尾辞、代名詞 |
| ng | 行末が `:` か `：` で、その直前のトークンが用言 |
| ng | 行末のトークンが助詞 |
| ng | 行末のトークンが動詞か助動詞で、活用形が連用形 |
| other | 上のいずれでもない |

英語は、行末が `:` の場合に
`the following` `as follows` `these` `below` `steps` `following`
のいずれかを含めば ok、含まなければ ng とする。
行末が `.` `!` `?` であれば ok とする。

厳密に見れば定形動詞があるかどうかを見るべきである。
それでも、この判別方だけで
AWS S3 ユーザーガイド（不完全30対完全145）と
Linux kernel（105対16）を分けられている。

違反の比率は `ng / (ok + ng)` とする。

### M2 項目数を地の文に書くこと

地の文（見出しを除く）で、次の形式を数える。

日本語は、数詞に続く `つ` `個` `点` `種` `類` のいずれかと、
`理由` `方法` `ポイント` `点` `要素` `ステップ` `手順` `方針` `特徴` `観点` `側面`
`利点` `欠点` `課題` `原則` `要因` `種類` のいずれかが続く形式。
`以下の3つ` `次の2点` のような形式。`3つある` `3つあります` のような形式。

英語は、`two` から `seven` または `2` から `7` に、
`reasons` `ways` `steps` `things` `types` `categories` `benefits` `points`
`factors` `approaches` `options` `principles` `rules` `components` `parts`
のいずれかが続く形式。

項目の数を地の文に書くと、項目を増やしたり減らしたりしたときに本文が壊れる。

この規則をどこまで当てるかには、まだ決めきれない点がある。
リストが続かない、ただの説明文で数を述べる場合も検出してしまう。
`tests/golden/input/ja_prose.md` がその例にあたる。

### M3 見出しの連番

見出しの行のうち、`#` の後に数字と `.` `、` `)` `章` `節` のいずれかが続くものを数える。

### M4 手で付与した番号

箇条書きの記号が `-` `*` `+` であって、その本文が数字と `.` か `)` で始まるものを数える。

### M5 項目のそろい

同じリストの中の項目について、末尾の形式を分割する。

日本語は、句点で終わる形式、体言で終わる形式、用言で終わる形式の三つに分類する。
英語は、ピリオドで終わる形と終わらない形の二つに分類する。

同じリストの中に二つ以上の形式が現れたら、そのリストを混ざっているとみなす。
混ざっている比率は `混ざったリストの数 / 項目が2個以上あるリストの数` とする。

### M6 時点に依存する語

次の語が出る数を数える。同じ行に二つあれば二つと数える。

日本語は `現在` `現時点` `最新の` `新しい` `今後` `将来的に` `まもなく` `既存の` `目下` `現行の`。

英語は `currently` `presently` `eventually` `soon` `latest` `newest` `newer`
`as of this writing` `at present` `in the future` `in the near future` `for now`。

英語の語彙は厳密な側に限定してある。
`new` `now` `future` `existing` を入れると、誤検出する数が多くなる。
これらを入れた場合、Google eng-practices の違反の比率が 6.13 で最も多くなった。
厳密な側では 0.58 で、すべてのコーパスの中で最も少なくなる。

この規則だけは、短い指示では遵守されない。
生成の前に置く層に入れる場合は、禁じる語を並べる必要がある。

### M7 列挙の末尾

日本語は行末が `など` か `等` であるもの。
英語は行末が `etc.` `and so on` `and more` であるもの。

地の文とリスト項目の両方を対象とする。

## 文体の規則

### register/rare-wago 文体から外れた和語

プロの日本語訳での頻度と比べて、偏って多く使われている和語の内容語を検出する。
対象は語種が和の内容語とし、数詞と1文字のカタカナは除く。
分野の用語は漢語やカタカナ語が多いため、和語に絞ることで誤検出を避けられる。

同じ語が3回以上出ていることを条件とする。
一度きりの語は、文体から外れているのか偶然の表現なのかを判別できない。

判定には二つの統計を使う。
Dunning (1993) の対数尤度比が 15.13 以上（自由度1で p < 0.0001）であることと、
Hardie (2014) の Log Ratio が 7.0 以上（参照の128倍）であることの両方を満たす場合に出す。
有意性だけでは足りない。普通の語を少し多く使っただけでも有意になるためである。

参照は `crates/suikou-core/data/register_ja.toml` に置いてある。
Kubernetes、MDN、Vue の日本語訳652頁、内容語およそ29万語から作った頻度表である。
入門書は文体が違うため入れない。2分野以上に現れる語だけを載せる。
作り直す手順は `research/lexshift/build_reference.py` にある。

`.suikou/terms.toml` と `.suikou/register-allow.toml` に載る語は対象から外す。
参照コーパスは Web の文書で作ってあり、計算や統計の語が手薄であるためである。

## ゴールデンテスト

`tests/golden/input/` の各ファイルに対する期待の値を
`tests/golden/expected/` に置いてある。

| ファイル | 何のためか |
|---|---|
| `ja_maintainability.md` | M1 から M7 を日本語で出させる |
| `en_maintainability.md` | 同様に英語で出させる |
| `ja_prose.md` | 地の文が中心の文書で、日本語の文書指標を確認する |
| `en_prose.md` | 同様に英語で確認する。英語の指標には445語以上が必要である |
| `en_escaped.md` | バックスラッシュを戻すかどうかで文分割が変わることを確認する |

期待の値は、構成した入力から作ってある。
実際のコーパスに対する回帰は `corpus/fetch.sh` で取ってきたものを使う。
ライセンスの都合で、コーパスそのものはリポジトリに入れない。
