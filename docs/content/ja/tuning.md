suikou のチューニングとは、管理対象の文書を実測し、その特性に適合する水準へ閾値を最適化する作業である。個人の好みに基づいて数値を書き換える作業ではない。

## 事前準備

設定を変更する前に、対象文書に対して `suikou check` を実行する。編集すべき設定ファイルは、どの検査レイヤーから指摘が報告されているかによって決まる。

```sh
suikou check docs/*.md --format text
```

調整の判断材料には、終了コードではなく指摘件数を用いる。終了コードは error が発生した場合にのみ 1 を返す仕様であるため、その確認だけでは warning を見落とす。

```sh
suikou check docs/*.md --format text | grep -c ':[0-9]*:[0-9]*:'
```

## suikou の検査対象とレイヤー構成

suikou の検査機構は3層で構成されており、レイヤーごとに設定の変更箇所が異なる。

| レイヤー | 検査対象 | 出力内容 | 代表例 |
|---|---|---|---|
| 局所の規則 | 行内の表記や表現 | 該当位置と修正方針 | `maint/list-lead-in`、`register/rare-wago` |
| 文書指標 | 文書全体の統計値 | 改稿の指示文 | `ja.kango_ratio`、`en.mattr100` |
| 構造の規則 | セクションの有無と配列順 | 不足しているセクション | `structure/missing-section` |

局所の規則は具体的な箇所を出力するため、修正対象を直接特定できる。文書指標は計測値をそのまま表示せず、書き換えの指示文に変換して提示する。構造の規則は、文書型が宣言された文書に限定して適用される。

言語ごとの解析方式として、日本語では形態素解析によって語種と活用形を判定し、英語では単語単位で判定する。この言語間の差異は `tokenizer.rs` の内部に集約している。

これらの指標および規則の厳密な仕様は [指標の定義]({{< relref "metrics.md" >}}) に記載されている。レイヤーの区分とそれぞれの責務は [設計]({{< relref "design.md" >}}) にまとめられている。

## 既定の閾値の根拠

組み込みの閾値は、プロの人間が執筆した文書の実測データから算出されている。人間の文体と AI の文体を識別できる境界値が採用されている。

具体例として、文末の連用中止の比を挙げる。ネイティブの人間による執筆では 2.00、人間による翻訳では 1.79 であるのに対し、AI の出力では 3.62 から 15.94 の範囲に分布する。この分布差に基づき、閾値は 3.0 に設定されている。

主観的な語感で数値を書き換えると、この判別性能が損なわれる。閾値を変更する際は、あらかじめ対象コーパスを計測し、実測データに基づいて値を決定する必要がある。

それぞれの指標がどのコーパスでどのような値を示したかの詳細は [指標の定義]({{< relref "metrics.md" >}}) に整理されている。検討の結果として不採用となった指標の一覧は、`corpus/baselines.toml` の `[rejected]` セクションに記録されている。

## 調整可能な項目と設定ファイル

目的に応じて編集する設定ファイルとセクションが異なる。

| 調整したい内容 | 設定箇所 |
|---|---|
| 閾値を全体で変更する | `.suikou/profile.toml` の `[thresholds]` |
| 文書の型ごとに閾値を変更する | `.suikou/profile.toml` の `[doctype.<型>]` |
| 指標の検査を無効化する | `.suikou/profile.toml` の `disable` |
| 局所の規則を型ごとに無効化する | `[doctype.<型>]` の `rules` |
| プロジェクト固有の名称を固定する | `.suikou/defined.toml` |
| 表記揺れの規則を追加または打ち消す | `.suikou/glossary.toml` |
| 専門分野の語彙を許可する | `.suikou/terms.toml` |
| 文書に型を割り当てる | `.suikou/structure.toml` の `[paths]` |

プロファイル全体を複製する必要はなく、記述した項目だけが組み込み設定を上書きする。

文書型ごとの設定は、以下の形式で記述する。

```toml
[doctype.readme]
reason = "入り口の文書であり、箇条書きが主になる"
rules = ["structure/long-paragraph"]

[doctype.readme.thresholds."ja.kango_ratio"]
value = 0.65
```

`reason` フィールドには調整を行った根拠や経緯を明記する。組み込みの調整設定に理由が記載されていることは、テストによって検証されている。同じ検討を後から繰り返す手間を省くためにも、判断の背景を残しておくことが重要である。

設定ファイルの書式と設定の優先順位は [指標の定義]({{< relref "metrics.md" >}}) の「閾値の調整」にまとめられている。用語集を構成する3ファイルの使い分けについては [書き方]({{< relref "writing.md" >}}) に記載されている。

## 調整の進め方

### 対象コーパスによる較正

`suikou baseline` コマンドを実行すると、指定したコーパスの実測値から閾値が自動算出される。

```sh
suikou baseline docs/ --lang ja > .suikou/profile.toml
```

較正不能な指標は設定出力から除外され、その理由が標準エラー出力に表示される。対象となるのは、サンプル数が不足している指標と、算出された境界が値域外となり一切発火しなくなる指標である。0 や仮の値で補完しない仕様のため、根拠を欠く閾値を見分けられる。

### 発火率に基づく妥当性の評価

ある指標が対象文書の 70% で発火している場合、文書側の品質問題ではなく閾値の不適合が疑われる。

著名な OSS の README 240件に対して既定の閾値を適用した計測結果を以下に示す。

| 指標 | README | 参照コーパス |
|---|---|---|
| `en.mattr100` | 70% | 15% |
| `en.prose_ratio` | 32% | 11% |

この発火率の差が、文書型ごとに閾値を独立させる設計の根拠となった。管理対象のコーパスについても、以下のコマンドで同様の集計を行える。

```sh
for f in docs/*.md; do suikou check "$f" --format text; done | grep -oE 'ja\.[a-z_]+' | sort | uniq -c
```

### 高い発火率の原因分析

発火率が過度に高くなる要因は3系統に大別でき、それぞれ確認手法と対処方針が異なる。

| 原因 | 検証方法 | 対処方針 |
|---|---|---|
| 文書の長さに対して分解能が不足している | 語数帯ごとに発火率を集計する | 型を問わず指標に適用下限を設ける |
| 文書型によって分布が異なる | 型ごとの発火率を比較する | 型別に閾値を変更する |
| 分布が広すぎて閾値による区分ができない | `suikou baseline` の報告を確認する | 該当の型では適用対象から除外する |

最初から文書型の差異を原因とみなすと、他の型にも同じ欠陥が残存する。比喩の標識の密度は文書型の問題に見えたものの、実際には文書の長さに起因する問題であった。詳細な経緯は [決めたことの記録]({{< relref "decisions.md" >}}) の D-43 に記録されている。

### 変更を一つずつ適用する

設定を一つ変更するたびに発火率を再計測する。複数の項目を同時に変更すると、どの修正が結果に寄与したかを切り分けられなくなる。

### info レベルの扱い

合格基準は error および warning が発生しない状態までとする。漢語率のような参考指標は info レベルとして報告されるため、指摘をゼロにする対象には含めない。

## 避けるべき調整

### 指標の最小化を目的化しない

漢語率をゼロにする目的で和語動詞への書き換えを進めたところ、文体の品質が損なわれた事例がある。漢語率を抑えるには、定着したカタカナ語を活用し、漢語の名詞を連続させない構成にする。この失敗の詳細は [決めたことの記録]({{< relref "decisions.md" >}}) の D-27 に記載されている。

### 指摘を単に非表示にする調整をしない

`disable` にすべての指標を列挙すれば指摘自体は表示されなくなる。しかし、指摘を抑止した分だけ文書に含まれる問題が検知できなくなる。

発火率が高い指標に対しては、まず発生原因を分類する必要がある。原因を検証しないまま検査から除外すると、同様の欠陥が他の文書に残ることになる。

### 主観的な語感で語彙を置換しない

指摘を受けた語の置換候補は、参照コーパスでの出現頻度を計測してから決定する。プロの日本語コーパス 400 万字において、`読み手` は 1件も出現しない一方、`読者` は 13件出現する。この差は実測するまで把握できない。

適切な語彙を選定する具体的な手順は [書き方]({{< relref "writing.md" >}}) の「選定の手順」に記載されている。

## 調整結果の検証

設定を変更したら、同一のコーパスに対して検査を再実行する。

```sh
for f in docs/*.md; do suikou check "$f" --format text; done | grep -c ':[0-9]*:[0-9]*:'
```

発火率が 10% 前後の水準であれば、閾値が対象文書の性質に適合している。70% のまま下がらない指標がある場合は、閾値調整の段階ではなく原因の切り分けが完了していない状態である。

指摘が 0件になった場合は、除外設定が過剰でないかを点検する。`.suikou/profile.toml` における `disable` と `rules` の記述行数を確認するとよい。

本ページでは設定の調整手順のみを扱う。各指標の定義は [指標の定義]({{< relref "metrics.md" >}})、設計上の根拠は [設計]({{< relref "design.md" >}})、個別の意思決定の経緯は [決めたことの記録]({{< relref "decisions.md" >}}) にそれぞれ記載されている。
