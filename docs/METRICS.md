# 指標の仕様

Rust 実装が満たすべき定義。`research/` の Python 実装が参照実装であり、
`tests/golden/` がその出力を固定している。

形態素解析器が lindera と fugashi で異なるため、完全一致は期待できない。
比較には許容誤差を設ける。許容範囲を超える指標が出た場合は、
どちらの実装が正しいかを個別に判断する。

## 前処理

順序が結果を左右する。次の順で行う。

1. YAML フロントマターを取り除く
2. フェンス付きコードブロックを取り除く
3. **バックスラッシュのエスケープを解除する**（`\.` を `.` に戻す）
4. HTML タグを取り除く
5. 行をブロックに分類する
6. 行内の記法（リンク、インラインコード、強調）を取り除く

手順3を飛ばすと文分割が成立しない。
AWS の doc_source がこの形式であり、解除しない場合の平均文長は3倍以上に膨らむ。
`tests/golden/input/en_escaped.md` がこの挙動を固定している。
解除前の文数は6、解除後は11である。

### ブロックの分類

| 種類 | 判定 |
|---|---|
| 見出し | 行頭が `#` 1個から6個とそれに続く空白 |
| リスト項目 | 行頭の空白に続いて `-` `*` `+` のいずれか、または数字と `.` か `)` 、その後に空白 |
| 表 | 行頭が `\|` |
| 引用 | 行頭が `>` |
| 地の文 | 上のいずれでもない非空行 |

### 対象範囲

| 指標の種類 | 対象 |
|---|---|
| 語彙系（MATTR、漢字率、漢語率、指示詞、形式名詞） | 地の文 ＋ リスト項目の本文 |
| 文構造系（文長、読点、文末、連用中止、テ形接続） | 地の文のみ |
| 書式系（地の文比率、箇条書き割合、太字） | 全行 |

語彙系を地の文だけで計算してはならない。
出力の大半が箇条書きであるモデルがあり、その場合に本文の8割以上を捨てることになる。

## 文の分割

日本語は `。` `！` `？` の直後で切る。
5文字未満、または日本語の文字を含まない断片は捨てる。

英語は spaCy の文分割に従う。
記号を除いたトークンが4個未満の文は捨てる。

## 日本語の指標

形態素解析は UniDic を使う。IPADIC では語種と活用形が得られない。

### ja.mattr100

窓幅100トークンの移動窓で、窓ごとの異なり語数を窓幅で割り、全窓で平均する。
トークン数が窓幅未満の場合は、全体の異なり語数をトークン数で割る。
トークンは表層形とする。

人間 0.559 から 0.581、AI 0.629 から 0.665。閾値 0.60。

### ja.renyo_per_1k（連用中止）

動詞であり、活用形が「連用形」で始まり、直後のトークンが読点である箇所を数える。
地の文の文字数（空白を除く）で割って1000倍する。

### ja.te_per_1k（テ形接続）

表層形が `て` または `で` であり、品詞細分類が接続助詞であり、
直後のトークンが読点である箇所を数える。同じく1000文字あたりに正規化する。

### ja.renyo_te_ratio

`renyo_per_1k` を `te_per_1k` で割る。分母が 0.05 未満の文書は比を計算しない。

人間ネイティブ 2.00、人間翻訳 1.79、AI 3.62 から 15.94。閾値 3.0。
最も強く分離する指標である。
テ形は話し言葉寄りで節を一体化し、連用中止は書き言葉寄りで節を並べる。
AI は後者に偏る。英語の現在分詞節の過剰と同じ現象にあたる。

### ja.keishiki_meishi_per_1k（形式名詞）

品詞が名詞であり、表層形が `こと` `もの` `ため` `よう` `点` `場合` のいずれかである
トークンを数える。1000文字あたりに正規化する。

人間 11.1、AI 4.99 から 6.95。閾値 8.5 を下回ったら指摘する。
**欠落の指摘である**ため、指摘位置を持たない。

ジャンルへの感度が高い。手順書では AI 側が 8.11 まで上がり閾値に接する。
ジャンル別の人間ベースラインが揃うまで severity は info とする。

### ja.demonstrative_per_1k（指示詞）

表層形が `これ` `それ` `この` `その` `これら` `それら` `こちら` `そちら` `ここ` `そこ`
のいずれかであるトークンを数える。1000文字あたりに正規化する。

人間 5.69 から 6.47、AI 1.38 から 3.39。閾値 4.5 を下回ったら指摘する。
これも欠落の指摘である。日本語のゼロ照応と関係する。

### ja.kango_ratio（漢語率）

自立語（名詞、動詞、形容詞、副詞、形状詞）のうち、
語種が `漢` であるものの割合を求める。
分母は語種が `和` `漢` `外` `混` のいずれかであるものの数とする。

人間 0.326 から 0.397、AI 0.455 から 0.519。閾値 0.42。
ジャンルとトピックへの感度が高いため severity は info とする。

### ja.kanji_ratio（漢字率）

対象テキスト中の漢字（U+4E00 から U+9FFF）の数を、
日本語の文字（ひらがな、カタカナ、漢字）の数で割る。

### ja.prose_ratio、ja.list_ratio

地の文比率は、地の文の文字数を「地の文＋リスト項目の本文」の文字数で割る。
箇条書き割合は、リスト項目の行数を全非空行数で割る。

いずれも空白を除いて数える。

## 英語の指標

検証を通ったのは三つだけである。
現在分詞節と名詞化は人間帯と重なった。
Reinhart らが報告した5.3倍という効果量は、文書作成というタスクに転移しない。

### en.mattr100

日本語と同じ定義。トークンは小文字化した表層形とし、記号と空白は除く。

人間 0.58 から 0.69、AI 0.72 から 0.82。閾値 0.71。
全ての AI 条件が全ての人間コーパスを上回る、最も頑健な指標である。

### en.prose_ratio

日本語と同じ定義。人間 0.66 から 0.97、AI 0.31 から 0.56。閾値 0.65。

### en.simile_marker_per_1k

次の語句の出現数を数え、1000語あたりに正規化する。大文字小文字は区別しない。

`like a` / `like the` / `as if` / `as though` / `akin to` / `similar to` /
`think of it as` / `imagine` / `analogous to` / `for example` / `for instance`

人間 0.84 から 2.54、AI 0.00 から 0.60。閾値 0.8 を下回ったら指摘する。

AI は隠喩的な語彙を多用する一方で、比喩であることを標識しない。
この指標は、隠喩を避けて直喩と例え話を使うという方針に対応する。

## M 系の規則

### M1 箇条書きの導入文

リストブロックの直前の非空行を導入文とする。
直前が見出しかリストである場合は判定しない。

日本語の分類は次のとおり。

| 結果 | 条件 |
|---|---|
| ok | 行末が `。` `！` `？` |
| ok | 行末が `:` か `：` で、その直前のトークンの品詞が名詞、接尾辞、代名詞 |
| ng | 行末が `:` か `：` で、その直前のトークンが用言 |
| ng | 行末のトークンが助詞 |
| ng | 行末のトークンが動詞か助動詞で、活用形が連用形 |
| other | 上のいずれでもない |

英語は、行末が `:` の場合に
`the following` `as follows` `these` `below` `steps` `following`
のいずれかを含めば ok、含まなければ ng とする。
行末が `.` `!` `?` であれば ok とする。

厳密には定形動詞の有無を見るべきだが、この判定だけで
AWS S3 ユーザーガイド（不完全30対完全145）と
Linux kernel（105対16）を分離できている。

違反率は `ng / (ok + ng)` とする。

### M2 項目数の明示

地の文（見出しを除く）で、次の形を数える。

日本語は、数詞に続く `つ` `個` `点` `種` `類` のいずれかと、
`理由` `方法` `ポイント` `点` `要素` `ステップ` `手順` `方針` `特徴` `観点` `側面`
`利点` `欠点` `課題` `原則` `要因` `種類` のいずれかが続く形。
`以下の3つ` `次の2点` のような形。`3つある` `3つあります` のような形。

英語は、`two` から `seven` または `2` から `7` に、
`reasons` `ways` `steps` `things` `types` `categories` `benefits` `points`
`factors` `approaches` `options` `principles` `rules` `components` `parts`
のいずれかが続く形。

項目数を地の文に書くと、項目を増減したときに本文が壊れる。

この規則の適用範囲には検討の余地がある。
リストが続かない純粋な説明文で数を述べる場合も検出される。
`tests/golden/input/ja_prose.md` がその例である。

### M3 見出しの連番

見出し行のうち、`#` の後に数字と `.` `、` `)` `章` `節` のいずれかが続くものを数える。

### M4 手動番号

箇条書きの記号が `-` `*` `+` であり、その本文が数字と `.` か `)` で始まるものを数える。

### M5 項目の平行性

同じリストブロック内の項目について、末尾の形を分類する。

日本語は、句点で終わる／体言で終わる／用言で終わるの三分類とする。
英語は、ピリオドで終わる／終わらないの二分類とする。

ブロック内に二つ以上の分類が現れたら、そのブロックを混在とみなす。
混在率は `混在ブロック数 / 項目が2個以上のブロック数` とする。

### M6 時点依存語

次の語の出現数を数える。

日本語は `現在` `現時点` `最新の` `新しい` `今後` `将来的に` `まもなく` `既存の` `目下` `現行の`。

英語は `currently` `presently` `eventually` `soon` `latest` `newest` `newer`
`as of this writing` `at present` `in the future` `in the near future` `for now`。

英語の語彙は厳格版に絞ってある。
`new` `now` `future` `existing` を含めると偽陽性が多くなる。
これらを含めた場合、Google eng-practices の違反率が 6.13 と最多になったが、
厳格版では 0.58 で全コーパス中の最小になった。

この規則だけは、簡潔な指示では守られない。
予防層に入れる場合は禁止語を列挙する必要がある。

### M7 列挙の末尾

日本語は行末が `など` か `等` であるもの。
英語は行末が `etc.` `and so on` `and more` であるもの。

地の文とリスト項目の両方を対象とする。

## ゴールデンテスト

`tests/golden/input/` の各ファイルに対する期待値を
`tests/golden/expected/` に置いてある。

| ファイル | 目的 |
|---|---|
| `ja_maintainability.md` | M1 から M7 を日本語で発火させる |
| `en_maintainability.md` | 同じく英語で発火させる |
| `ja_prose.md` | 地の文中心の文書で日本語の文書指標を確認する |
| `en_prose.md` | 同じく英語で確認する。英語の指標は445語以上が必要 |
| `en_escaped.md` | バックスラッシュ解除の有無で文分割が変わることを確認する |

期待値は合成した入力から作ってある。
実際のコーパスに対する回帰は `corpus/fetch.sh` で取得したものを使う。
ライセンスの都合でコーパス本体はリポジトリに入れない。
