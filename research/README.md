# research

research は探索と較正に使う Python のコード群であり、本番の処理経路には組み込まない。

すべての指標は、ここに置いたコードの出力を基準にする。
Rust の実装が同じ値を返すかどうかは、ゴールデンテストで確認する。

## 必要なパッケージの導入

```sh
pip install fugashi unidic-lite spacy --break-system-packages
python -m spacy download en_core_web_sm
```

## 含まれるファイル

| ファイル | 内容 |
|---|---|
| `jametrics.py` | 日本語の文書の指標 |
| `enmetrics.py` | 英語の文書の指標 |
| `mcheck.py` | M1 から M7 までの規則 |

## 実行方法

```sh
python jametrics.py 'corpus/**/*.md'
python enmetrics.py 'corpus/**/*.md'
python mcheck.py   'corpus/**/*.md'
```

どのスクリプトも、結果を JSON 形式で標準出力に書き出す。
この出力を `tests/golden/expected/` にそのまま置き、期待値として使う。

## このレイヤーを本番と分ける理由

深い構文解析を必要とする指標ほど、実験の設計によって結果が変わりやすい。
ここでは分詞節、名詞化、修飾の積み重ね、係り受けの距離を試した。
どの指標も人間の文書の値の範囲と重なったので、採用しなかった。

ここで有効だと確かめた指標だけを、Rust の実装へ移す。
検証を経ていない指標を本番で使わないためである。

spaCy は読み込みに2秒から5秒かかる。
hooks から繰り返し呼び出すと、この読み込み時間がそのまま利用者の待ち時間になる。
したがって、このレイヤーは本番の経路に入れられない。

## 変更するときの注意

ここで生成した期待値は、Rust 側の実装が満たすべき条件になる。
そのため、このディレクトリのコードを変更したら、期待値も生成し直す。
生成し直した後は、Python と Rust の実装が同じ値を返すことを確認する。
